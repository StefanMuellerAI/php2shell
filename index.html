Befund für

Ob ein Server wirklich angreifbar ist, ließe sich von außen nur mit echten Angriffsversuchen testen. Deshalb zählt die PHP-Version. Die eingegebene Adresse wird für die Prüfung an unseren Prüfserver übermittelt und nicht gespeichert. Eine eingetippte Version verlässt Ihren Browser nicht.

    Wo finde ich meine PHP-Version?

    Entscheidend ist die letzte Stelle: 8.3.14 ist betroffen, 8.3.36 nicht.

    WordPress

    Werkzeuge → Website-Zustand → Bericht, dort den Bereich „Server“ aufklappen, Zeile „PHP-Version“. Direkt dorthin führt die Adresse ihre-domain.de/wp-admin/site-health.php?tab=debug. Die Seite sehen nur Administratoren.

    Ein WordPress-Update ändert die PHP-Version nicht. Das erledigt der Server.

    Im Kundenmenü des Hosters

    Melden Sie sich im Kundenmenü an und suchen Sie nach „PHP-Einstellungen“, „PHP-Version“ oder den Einstellungen Ihres Webspace. Dort steht oft nur die Linie, etwa „8.3“. Die vollständige Nummer zeigt dann Ihr CMS, oder der Hoster nennt sie auf Nachfrage.

    TYPO3

    Im Backend oben rechts das Info-Symbol „System-Information“ öffnen, Zeile „PHP-Version“ (nur für Administratoren). Alternativ System → Umgebung (TYPO3 14) bzw. Verwaltungswerkzeuge → Umgebung (TYPO3 12/13), dort nur für System-Maintainer.

    Joomla

    System → Systeminformationen, Zeile „PHP-Version“ (als Super User).

    Drupal

    Berichte → Statusbericht, Zeile „PHP“ (als Administrator).

    Was nicht hilft

    • Updates von WordPress, TYPO3 & Co. oder ihren Plugins. Die Lücke steckt in PHP selbst.
    • Der Wartungsmodus des CMS. PHP verarbeitet die Anfrage, bevor das CMS ihn überhaupt prüft.
    • Sicherheits-Plugins im CMS. Sie greifen erst, wenn PHP die Anfrage schon verarbeitet hat.
    • Fehlermeldungen ausblenden. Laut PHP-Advisory schützt das nicht.
    • Nur die Hauptwebsite prüfen. Webmail, Cloud-Speicher oder Intranet auf PHP sind genauso betroffen.

    Was ist passiert?

    PHP2Shell ist der Spitzname für zwei Lücken im PHP-Interpreter selbst: CVE-2026-109618 und CVE-2026-109619, beide mit CVSS 9.2 (Version 4.0) als kritisch eingestuft. Wer sie ausnutzt, kann ohne Anmeldung eigenen Code auf dem Webserver ausführen. Laut den Entdeckern lässt sich außerdem Arbeitsspeicher des Servers auslesen, in dem Passwörter oder Schlüssel stehen können.

    Laut den Entdeckern reicht der älteste betroffene Code bis PHP 5.4 aus dem Jahr 2012 zurück. Das PHP-Projekt stuft alle PHP-Installationen, die Webanfragen bedienen, als gefährdet ein, schon in der Standardkonfiguration, ob als Apache-Modul (höchstes Risiko) oder über PHP-FPM. Das betrifft einen Großteil aller Websites, von WordPress über TYPO3 bis zu Online-Shops, Webmail und Cloud-Diensten.
